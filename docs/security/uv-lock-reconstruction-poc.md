# POC: uv universal lock and clean Python reconstruction

- **Issue:** #86
- **Scope:** Windows x64, CPython 3.12 and 3.15
- **uv candidate:** 0.13.7 (pinned for this experiment; not yet an approved CPIE tool)
- **Status:** manifest scaffold only; lock generation and clean reconstruction are pending.

## Objective

Determine whether one universal `uv.lock` can represent the tested Windows CPython 3.12 and 3.15 lanes while keeping the PyTorch CPU extra restricted to Python 3.12. Do not create separate lockfiles unless resolution or installation evidence requires them.

This is an isolated POC manifest under `poc/supply-chain/python/`. It is not the production CPIE dependency manifest and does not approve any package version as a project baseline.

## Dependency scope

- The base project lists the direct imports used by the quantitative workload probe, pinned to the exact versions recorded in the successful local Python 3.12.10 run.
- The `compatibility` dependency group contains the additional direct imports exercised by the existing general stack probe. uv will resolve and lock their transitive dependencies.
- The `pytorch-cpu` extra points to the official PyTorch CPU wheel index and is marked for Python versions below 3.13, matching the tested 3.12 lane. Python 3.15 must not install this extra.
- `tool.uv.environments` limits universal resolution to the two intended Windows CPython lanes. Python 3.13/3.14 and other platforms are not part of this POC's compatibility claim.

The lockfile must be generated by uv, never hand-authored. It must be committed only after successful resolution and review.

## Install uv without changing Python environments

Official installation documentation: https://docs.astral.sh/uv/getting-started/installation/

For this POC, install the pinned standalone Windows build (0.13.7) in the user profile:

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/0.13.7/install.ps1 | iex"
```

Close and reopen PowerShell if needed, then verify:

```powershell
uv --version
```

Expected: `uv 0.13.7`. This installs a separate executable; it must not install packages into either existing `.venv-poc-312` or `.venv-poc-315`.

## Generate and review the lockfile

Run from the repository root on this branch:

```powershell
uv lock --project .\poc\supply-chain\python
uv lock --check --project .\poc\supply-chain\python
```

Review `poc/supply-chain/python/uv.lock` before committing it. Confirm that:
- both Windows CPython lanes are represented;
- the PyTorch CPU dependency is constrained to Python 3.12;
- package artifacts include hashes;
- no unexpected source builds, VCS dependencies, editable dependencies or unapproved indexes appear;
- the lock contains all dependency groups and extras, including the compatibility group and PyTorch extra.

If resolution fails, preserve the complete error output. Do not immediately split the lockfile: identify the exact package, marker, wheel or index constraint first.

## Clean reconstruction — isolated from existing environments

The following creates new environments under the Windows temporary directory. It does not touch `.venv-poc-312/`, `.venv-poc-315/` or existing `poc-results/`.

### Python 3.12 + PyTorch CPU + quantitative workload

```powershell
$env:UV_PROJECT_ENVIRONMENT = Join-Path $env:TEMP "cpie-uv-312"
uv sync --locked --project .\poc\supply-chain\python --python 3.12 --group compatibility --extra pytorch-cpu
& "$env:UV_PROJECT_ENVIRONMENT\Scripts\python.exe" .\scripts\poc\python_cpi_workload_probe.py --output (Join-Path $env:TEMP "cpie-uv-results\python-cpi-workload-3.12.json")
```

### Python 3.15 — compatibility imports without PyTorch

```powershell
$env:UV_PROJECT_ENVIRONMENT = Join-Path $env:TEMP "cpie-uv-315"
uv sync --locked --project .\poc\supply-chain\python --python 3.15 --group compatibility
& "$env:UV_PROJECT_ENVIRONMENT\Scripts\python.exe" -c "import fastapi, lightgbm, numpy, pandas, polars, psutil, pyarrow, pydantic, scipy, sklearn, statsmodels, xgboost; print('PYTHON_315_IMPORTS_PASS')"
```

Record the full output and exit codes. Do not run both installations concurrently on the 16 GB development machine.

## Reproducibility checks

After both environments pass:

```powershell
uv lock --check --project .\poc\supply-chain\python
uv tree --project .\poc\supply-chain\python --locked
Get-FileHash .\poc\supply-chain\python\uv.lock -Algorithm SHA256
```

Repeat each `uv sync --locked` after deleting only the two new temporary POC environments, if and only if their paths have been verified to be exactly `$env:TEMP\cpie-uv-312` and `$env:TEMP\cpie-uv-315`. Never use `git clean`, broad wildcard deletion or removal of the user's pre-existing virtual environments.

## Interpretation and limitations

- One lockfile is accepted only if both clean syncs succeed with the same committed `uv.lock` and the expected lane-specific package selection.
- A successful resolver run is not proof that all target packages install on both interpreters; clean sync and runtime checks are mandatory.
- A lockfile is not an SBOM, vulnerability scan, license audit, provenance attestation or production approval.
- The pinned package versions reproduce the tested workload's direct dependency set, but the additional compatibility-group versions are selected by the lock and must be reviewed before approval.
- The POC covers Windows x64 CPython 3.12/3.15 only. It does not validate Linux/macOS, GPU/CUDA, production deployment or all supported CPIE components.
- Do not upload local JSON reports containing personal machine metadata without reviewing them first.
